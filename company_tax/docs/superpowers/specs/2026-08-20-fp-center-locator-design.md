# 가까운 FP센터 찾기 설계 (company_tax 부속 도구)

작성일: 2026-08-20

## 배경 및 범위

삼성생명 FP센터는 전국 8곳이다. FC가 상담 중 "지금 위치에서 가장 가까운 센터가 어디인가"를 확인할 수 있는 조회 화면을 만든다.

이 도구는 세액 계산과 무관하므로 `company_tax/fp-center/` 에 **독립 페이지**로 분리한다. 기존 `tax-review/index.html`(2,044줄)은 건드리지 않는다.

### 범위에서 제외한 것

- **지도 임베드**. 화면 안에 지도를 띄우지 않고, 각 센터에 카카오맵 바로가기 링크만 제공한다. 임베드는 API 키가 코드에 노출되거나(제4조 위반) 서버 프록시가 필요한데, 조회 도구 하나를 위해 company_tax 최초의 서버를 세우는 것은 "지금 필요한 만큼만 만든다"는 원칙에 어긋난다.
- **실제 이동거리·소요시간**. 직선거리로 계산한다. 전국 8곳뿐이라 이동거리를 쓰나 직선거리를 쓰나 상위 3곳이 뒤집힐 일이 거의 없고, 이동거리는 길찾기 API가 필요해 서버·키가 다시 붙는다.
- **FP센터 외 지점·사업부**. 첨부 자료에 있는 FP센터 8곳만 다룬다.

### 나중에 되돌릴 수 있는 지점

지도 임베드가 필요해지면 이 설계 위에 지도 영역만 얹으면 된다. 거리 계산·데이터·화면 구조는 그대로 재사용된다.

## 대상 사용자 및 배포

주 사용자는 **FC**이지만, 사내망이 아닌 **외부(인터넷)에 배포**한다. FC가 외근 중에도 쓸 수 있어야 하기 때문이다.

이 때문에 페이지는 사실상 대외 공개물로 취급한다. 접근 통제를 두지 않는 이상 고객도 열람할 수 있으므로, 위치정보 수집에 대한 **고지와 명시적 동의**를 화면에 포함한다.

- 위치 요청은 버튼 클릭으로만 발생한다(자동 실행 없음) — 이것이 명시적 동의 행위다.
- 버튼 옆에 **수집 항목·이용 목적·보관 여부**를 한 줄로 고지한다: "현재 위치는 가까운 센터를 계산하는 데만 쓰이며 저장·전송되지 않습니다."
- 실제로 저장·전송하지 않으므로 고지 내용과 구현이 일치한다.

접근이 실제로 FC로 한정되는 비공개 URL이라면 고지 문구는 제거해도 무방하다. 반대로 고객 대상 홍보물로 쓰이게 되면 준법감시 심의를 별도로 받아야 한다.

## 아키텍처

프레임워크 없이 순수 HTML/JS. 거리 계산을 화면에서 분리해 Node.js로 자동 테스트한다.

```
company_tax/fp-center/
├── centers.js        # 센터 8건 데이터 + 준법감시 메타 (DOM 의존 없음)
├── nearest.js        # 거리 계산·정렬 (순수 함수, Node에서도 동작)
├── nearest.test.js   # 테스트
└── index.html        # 화면
```

### 네트워크 호출은 0줄

좌표 변환(지오코딩)은 **company_tax 밖에서 1회 실행**하고 결과 좌표만 `centers.js`에 커밋한다. 프로젝트 안에는 `fetch`·`XMLHttpRequest`가 한 줄도 들어가지 않으므로 NFR-03·04("네트워크 API를 코드에 포함하지 않음으로써 구조적으로 보장")가 그대로 유지된다.

카카오맵 링크는 `<a href>` 이동이므로 데이터 전송이 아니다. 사용자가 클릭했을 때만 새 창이 열린다.

### 현재 위치의 수명

```
Geolocation 콜백 → 지역 변수 → 거리 계산 → 화면 렌더 → 소멸
```

`localStorage`·`sessionStorage`·쿠키에 저장하지 않고, 어디로도 전송하지 않는다. 제4조를 조항 그대로 통과한다.

## 동작 흐름

```
페이지 열기 → 8곳 전체 리스트 표시 (위치 없이도 완결된 화면)
  → [가까운 센터 찾기] 클릭
  → 브라우저 위치 권한 요청
  → 현재 좌표 획득
  → 8곳과의 직선거리 계산 (하버사인)
  → 가까운 순 3곳을 상단에 거리와 함께 표시
```

**자동 실행하지 않는다.** 페이지 진입 즉시 권한 팝업이 뜨면 반사적으로 거부하는 경우가 많고, 위치 수집은 사용자가 의도했을 때만 일어나는 것이 맞다.

### 화면 구성

위치 획득 성공 시 화면은 두 영역으로 나뉜다.

```
[가까운 센터 3곳]     ← 강조 영역. 거리 표시. 가까운 순.
[전체 FP센터 8곳]     ← 항상 존재. 상단 3곳도 중복 포함하며 지역명 순 고정.
```

전체 목록에서 상위 3곳을 빼지 않는다. 목록이 상황에 따라 늘었다 줄었다 하면 "내가 아는 그 센터가 왜 없지"라는 혼란이 생긴다. 전체 목록은 항상 8곳 그대로 두고, 상단 강조 영역만 위치에 따라 나타난다.

위치 획득에 실패하면 상단 강조 영역이 생략되고 전체 목록만 남는다.

각 항목 구성: 센터명 · 주소 · 전화(`tel:` 링크) · 카카오맵 바로가기. 거리는 상단 강조 영역에서만 표시하며 **km 소수점 첫째 자리까지** 반올림한다(예: `12.4km`). 1km 미만은 `1km 이내`로 표기한다.

카카오맵 링크는 키가 필요 없는 공개 URL을 쓴다.

```
https://map.kakao.com/link/map/{센터명},{위도},{경도}
```

### 좌표 확보 — 완료 (2026-08-20)

거리 계산에는 8곳의 위경도가 필요하다. 추정값을 넣으면 순위가 틀리므로 실제 값을 확보했다.

카카오 로컬 REST API(주소 → 좌표)를 **프로젝트 밖에서 1회** 호출해 8곳 전부 변환했고, 결과는 위 표에 있다. REST API 키는 저장소 밖 파일(`kakao-rest-key.txt`, `.gitignore` 등록)에서 읽었으며 소스에 포함되지 않는다. 변환 스크립트는 저장소 밖에 두고 폐기했다 — 자료 갱신 시 10줄짜리를 다시 만들면 된다.

8곳 모두 도로명주소로 정확히 인식됐고 좌표는 각 지역 도심에 떨어진다. 런타임에는 지오코딩을 하지 않는다.

## 거리 계산 (nearest.js)

하버사인 공식으로 두 좌표 간 대권거리를 구한다. 지구 반지름 6371km.

```javascript
distanceKm(lat1, lng1, lat2, lng2) -> number   // km, 반올림하지 않은 원값

nearest(현재좌표, centers, n = 3) -> [{ ...center, 거리km }]
// 가까운 순 최대 n개. centers가 n보다 적으면 있는 만큼만 반환한다.
// 반올림은 화면 계층의 책임이며 이 함수는 원값을 그대로 넘긴다.
```

DOM에 의존하지 않는 순수 함수라 Node에서 그대로 테스트된다. Geolocation은 이 모듈 밖에 두고, 좌표를 **인자로 받는다**.

## 에러 처리

**원칙: 위치는 전제가 아니라 향상이다.** 위치를 얻지 못해도 화면은 완결되어야 한다. 8곳 전체 리스트는 항상 보이고, 위치를 얻으면 가까운 3곳이 상단으로 올라오며 거리가 붙을 뿐이다.

| 상황 | 동작 |
|---|---|
| 사용자가 권한 거부 | 전체 8곳 표시 + "위치를 허용하면 가까운 순으로 정렬됩니다" |
| 위치 확인 실패·타임아웃(10초) | 동일 |
| `navigator.geolocation` 미지원 | 동일 (버튼 자체를 숨김) |
| 좌표가 한국 밖 | 전체 표시 + 안내 (해외 로밍·VPN 가능성) |

### HTTPS 요구사항

**Geolocation API는 보안 컨텍스트(HTTPS 또는 localhost)에서만 동작한다.** 외부 배포이므로 HTTPS가 기본이라 문제되지 않지만, 이는 **배포 요구사항**이다. `http://`로 배포하거나 파일을 직접 열면(`file://`) 위치 기능이 항상 폴백으로 떨어진다.

로컬 개발·테스트는 `http://localhost` 에서 하면 정상 동작한다.

## 테스트 계획

원칙 제3조에 따라 테스트를 먼저 작성하고 실패를 확인한 뒤 구현한다. 기대값은 하버사인 수식으로 직접 산출해 고정한다.

| 대상 | 케이스 |
|---|---|
| `distanceKm` | 알려진 두 지점 간 거리 (예: 서울시청↔부산시청) |
| `distanceKm` | 동일 좌표 → 0 |
| `nearest` | 강남 좌표 입력 시 강남·서울FP센터가 상위에 오는지 |
| `nearest` | 제주 등 원거리 좌표에서의 순서 |
| `nearest` | 요청 개수가 센터 수보다 많을 때 |
| 만료 경고 | 만료 61일 전(미표시) / 60일 전(표시) / 만료 후(문구 변경) |

Geolocation 자체는 테스트하지 않는다. 좌표를 인자로 받는 순수 함수로 분리해 우회한다.

## 주의사항 / 리스크

1. **준법감시필 만료 (2026-10-27)** — 68일 남았다. 만료 후에도 화면이 그대로 노출되지 않도록 경고 배너를 넣지만, 갱신 자체는 사람이 해야 한다.
2. ~~**주소 전사 오류**~~ — **해소됨 (2026-08-20).** 8곳 모두 카카오 주소 DB가 도로명주소로 정확히 인식했고, 판독이 애매했던 "부산진구"도 확인됐다.
3. **HTTPS 배포 필수** — 외부 배포로 확정되어 해소. 다만 배포 시 HTTPS 여부를 반드시 확인한다. `http://`면 위치 기능이 조용히 죽고 폴백만 뜨므로 눈치채기 어렵다.
4. **센터 정보 변경** — 이전·통폐합·번호 변경 시 `centers.js`를 수정하고 좌표를 다시 뽑아야 한다. 런타임 지오코딩이 없으므로 자동 반영되지 않는다. 의도한 트레이드오프다.
5. **대외 공개물 취급** — 외부 배포이므로 고객이 열람할 수 있다. 위치정보 고지 문구를 화면에 넣지만, 이 페이지를 고객 대상 홍보물로 활용하게 되면 준법감시 심의를 별도로 받아야 한다. 심의 여부는 사람이 판단할 사항이다.
